# Strong L336 + transductive AQE: внутреннее сравнение, 29.09.2026

Пользователь выбрал strong-augmentation DINOv2 ViT-L/14@336 как финальный
энкодер и попросил применить к нему AQE. Вес проверен на Mac: 1 217 580 060
байт, SHA256 `de955ba6ec3a2cb232708eddd1b1b57400bc449405d6d9e2ab25c791a46e617f`;
строгая загрузка и один нормированный 1024D-вектор на CPU прошли.
Показанные ниже числа — **внутренние organizer dev/calibration**, не скрытый
тест и не конкурсный score. Holdout не открывали.

## Поиск на одних и тех же strong-эмбеддингах

Протокол: FP32, cosine; для каждого запроса исключены все изображения той
же камеры. AQE — однократное расширение всех эмбеддингов набора по пяти
ближайшим соседям, `z′=norm(0.75z+0.25 mean(top5(z)))`, затем cosine по
обновлённым векторам. Это **transductive** метод: представления галереи
зависят от всего набора запросов.

| Внутренний срез | Метод | mAP | Rank-1 | Rank-5 |
|---|---|---:|---:|---:|
| Dev, 1 449 запросов / 231 ID | Strong cosine | 74.0484% | 74.2581% | 87.9917% |
| Dev | Strong + AQE | **77.6310%** | **77.0186%** | 87.1636% |
| Calibration, 929 запросов / 154 ID | Strong cosine | 81.3685% | 83.7460% | 92.1421% |
| Calibration | Strong + AQE | **84.6474%** | **84.8224%** | **93.4338%** |

AQE прибавил к strong cosine **+3.5826 п.п. mAP на dev** (парный
vehicle-ID bootstrap 95% CI: +2.4957…+4.7173) и **+3.2789 п.п. на
calibration** (+2.1468…+4.5220). На dev Rank-5 снизился на 0.8282 п.п.
(CI −2.0154…+0.2727); на calibration вырос на 1.2917 п.п.
(CI −0.1080…+2.8848). Эти интервалы учитывают повторную выборку ID, но
не устраняют исследовательскую повторную настройку по dev/calibration.
Против ранее измеренного mild+AQE прирост strong+AQE составляет только
+0.3025 п.п. dev и +1.0650 п.п. calibration mAP; отдельного парного
интервала между этими двумя энкодерами нет.

Более близкий к API open-set с раздельными query/gallery даёт на известных
запросах dev mAP **80.8855 → 83.2796%**, Rank-1 **77.2803 → 79.2703%**,
Rank-5 **91.8740 → 92.7032%**; calibration mAP **84.6816 → 88.6983%**,
Rank-1 **81.0959 → 85.2055%**, Rank-5 **93.4247 → 92.6027%**. Размеры:
dev 1 036 запросов, из них 603 известных; calibration 652 / 365.
Ухудшение calibration Rank-5 здесь важно и не должно исчезать из защиты.

## Отказ от сомнительных кандидатов — отдельная метрика

Старый boosting-файл от mild-веса использовать нельзя: привязка к модели
и распределение cosine изменились. Для strong-кандидата заново обучена
portable shallow-boosting политика на calibration: порог cosine **0.462**,
booster threshold **0.151**, `preserve_first_n=3`.
AQE меняет порядок, а политика получает **исходный cosine** выбранных AQE
top-10, временно сортированный по cosine для входа в калибратор; возвращаемые
`similarity`/`confidence` остаются raw cosine, не вероятностью.

| Open-set с новой strong-политикой | Pair-F1 | Query correct-ID F1 | TNR |
|---|---:|---:|---:|
| Dev, cosine | 57.1140% | 69.3122% | 78.0600% |
| Dev, AQE | 57.1332% | 69.3122% | 78.0600% |
| Calibration, cosine | 69.8837% | 76.1769% | 79.0941% |
| Calibration, AQE | 69.8837% | 76.1769% | 79.0941% |

Dev — перенос обученной на calibration политики; calibration F1 здесь
показан на самой обучающей выборке и **не независимая оценка**. Политика
обучалась на cosine-кандидатах, не переобучалась под AQE. Улучшение mAP
не означает автоматического прироста F1/TNR. На dev strong hybrid против
strong cosine-порога улучшил pair-F1 56.5246→57.1140%, но ухудшил
query-F1 70.8995→69.3122%; этот компромисс требует явной оговорки.

## Путь внедрения и ограничения

Пакетный API принимает ZIP или отдельные файлы с BBox CSV, извлекает
эмбеддинги по одному кадру и **один раз** ранжирует весь валидный набор
запросов против одной versioned-галереи. Локальный код AQE воспроизводит
исследовательскую формулу на детерминированном тесте. `/solo` пока остаётся
exact cosine: transductive AQE для одного пришедшего запроса не совпадает
с измеренным пакетным протоколом. В ответе API отдельно маркируются
`ranking_algorithm`, `query_cohort_size`, `ranking_score`; confidence —
сырой cosine. В имеющемся code path соседства вычисляются точно с
ограничением промежуточной RAM, но время растёт квадратично от размера
cohort+gallery. Нельзя переносить измеренные ~0.197/0.069 с для расширения
на dev/calibration на end-to-end HTTP/GPU latency или миллионную галерею.

Для сдачи добавлен отдельный AQE-режим экспортера: `embeddings.npy`
содержит **уточнённые** векторы запросов, затем галереи в порядке их CSV.
Их cosine воспроизводит top-10 из `submission.csv` при независимом
round-trip тесте; `candidates.csv` использует исходный cosine до AQE для
отказа. Старый exact-cosine экспорт сохранён. Если жюри пересчитает
расстояния из `.npy`, оно увидит тот же AQE-порядок. ТЗ прямо не запрещает
postprocessing векторов без меток, но не уточняет, примет ли его эталонный
скрипт; `/v1/embeddings` на одном изображении возвращает исходный, не
AQE-вектор. Эту разницу необходимо явно показать жюри.

**Статус на момент записи:** исследовательские результаты готовы; локальные
Python-тесты 58/58, JS 11/11 и строгое открытие нового веса прошли.
Реальный smoke на примерах 10 исходных кадров галереи и 2 запроса с BBox
выдал нормированные `10×1024` и `2×1024` вектора и AQE top-10;
6,21 с CPU после загрузки энкодера — не оценка скорости жюри. Для сквозного
запуска выбранного пакета ещё нужны strong boosting sidecar, версия
манифеста калибровки, пересоздание эмбеддингов галереи новым весом и
проверка реального backend→ML запроса. Старую mild-галерею нельзя
подставлять под новый SHA. Git/backend по умолчанию не переключён до этих
проверок. Официального скрипта нет.
